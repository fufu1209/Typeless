### 修掉的真缺口：v2.5.4 把「文件缺失」判成「已完成」
`desktopOnboardingIsIncomplete()` 读不到 `app-onboarding.json` 就 return false，
原意是「没装 Typeless 不该误报警」，但同时放过了「装了、文件被升级/重装删掉」——
补丁永不触发，而 Typeless 冷启动又按默认值重建文件 → 重新变回未完成，白等一整轮。
修法：状态拆三态 `.complete/.incomplete/.missing`，缺失且 `typelessAppPath() != nil` 才需要处理。
**实测**：删掉文件后启动 2.5.5，日志出现「启动自检：检测到…未完成」；
v2.5.4 在该场景下一行日志都不会打。写入路径与 v2.5.4 共用，未重复验证。

### 引导补丁新增三道保险
- 写前备份 `app-onboarding.json.switchboard-orig.bak`（只留第一份）
- 写完回读校验，写成功≠生效
- 自愈补写 app-storage.json（best-effort，缺 userData 就跳过）
- 5 分钟常驻巡检 `startOnboardingGuardIfNeeded()`（v2.5.4 只有冷启动一次）

### 额度周期时区（用户 ③ 的隐藏问题）
本机系统时区是 **Asia/Bangkok(+0700)**（不是我猜的，是 `readlink /etc/localtime` 实测），
用户在深圳 +0800 → 「周一 00:00」整体偏移 1 小时。
新增 `QuotaCycleClock`（Core，NSLock 保护，iso8601 日历天然周一为首日），
UI 倒计时 / 复活判定 / 看门狗排程三处共用，不再各拿 `Calendar.current`。
settings 加 `quotaCycleTimeZoneIdentifier`（空串=跟随系统，老 store.json 无需迁移），
额度守护页可切 UTC+8。**当前值仍是空串，待用户决定是否锁 UTC+8**。

### 清理：守护日志 24MB → 3.1MB
`quota-guard-daemon.log` 10MB + `quota-guard-launchd.out.log` 15MB，共 47891 轮巡检。
新增 `LogFileRotator`：**必须原地截断**（seek+write+truncateFile），
不能 `write(to:atomically:)` 换 inode —— launchd 持有的是老 fd，换文件会让它继续往
已删除的 inode 写，磁盘不释放、新日志也看不到。
超限时**循环砍到 2MB 以内**（只砍一次的话 15MB 要重启三次 App 才见效）。

## v2.5.5 续（00:20-00:35）引导补丁写入层下沉 Core

### 为什么要动
上一轮只验证了「检测」分支，「写盘」分支依然悬空 —— 补丁只在
「Typeless 没在运行」时才允许写，而用户的 Typeless 基本常开，
等于这段逻辑从来没被真正测过，每次改动只能靠「读日志看有没有报错」来猜。

### 做法
把纯文件读写下沉到 `Sources/TypelessSwitchboardCore/OnboardingPatchWriter.swift`
（路径全靠参数注入，不依赖 AppKit、不碰进程）。App 层的
`SwitchboardStore+OnboardingPatch.swift` 只留编排：
「什么时候该写 + 写完记什么日志」。同时把状态判定、备份、读邮箱、判新用户
一并下沉，消除 App/Core 两份实现（之前测试里还抄了一份判定逻辑，现在删掉了）。

下沉后新增 27 条断言，覆盖以前构造不出来的现场：
文件被删→从零补写 / 引导被重置→覆盖且不吞其他键 / 备份只留第一份 /
7 平台全补齐 + macos 补 app_version+completed_at / 邮箱不符抛错不静默改号 /
无 userData 抛 missingUserData 供 App 降级 / 读邮箱与判新用户。

### 一条可复用经验
**「只在某个外部条件满足时才跑的代码」要尽早把纯逻辑剥离出来注入测试。**
这类代码在真机上永远等不到触发条件，测试覆盖率为零，
出问题时只能靠人肉复现。判断标准：函数里如果混了「读外部状态」和「算/写结果」，
就把后半段抽成注入式的纯函数。

## B. 2.9.0 新修

| # | 问题 | 为什么是 bug | 状态 |
|---|---|---|---|
| B1 | 热备注册在巡检里 `await` | 注册分钟级；巡检不返回 → 跨进程锁不释放 → 守护每分钟被挡在门外，额度跟着陈旧 | ✅ 后台任务 |
| B2 | `runProcess` 超时只 terminate 直接子进程 | `node → npm → Playwright → Chromium` 后代继续跑，进程残留、看门狗反复触发 | ✅ 杀整棵进程树 |
| B3 | 会话 payload 走 argv | `refresh_token` 有效期约 1 年，会出现在 `ps` 里，同机进程可见 | ✅ stdin |
| B4 | 注册前不保存「当前真实会话」 | 失败恢复只能用账号里上次同步的旧 payload | ✅ 注册前 `--local-only` 抓一次 |
| B5 | 修桥可能打断换号 | 自动修复会重启 Typeless，若换号正在注入会话会被打断 | ✅ `isSwitchBusy` 守卫 |

| B8 | 「打开 Typeless」文案谎报端口 | 已在运行的实例不会补端口，UI 却说「直读端口 9333」 | ✅ 文案诚实化 |
| B9 | 没有一键恢复登录的入口 | 用户只能靠换号/注册绕 | ✅ 诊断页「修复登录」+ `--repair-login` |
| B10 | 没有一眼看全的健康报告 | 排障要翻日志 | ✅ `--health` |

## D. 数据面观察（供后续决策）

- 账号池：73 个（可用 48 / 用尽 15 / 暂停 10 / 待确认 9），无重复邮箱、payload 全部可解析、refresh_token 无一过期。
- 换号历史（7 天）：8 次，成功 6 / 失败 2，中位耗时 23.2 秒。
- 待确认 9 个是注册流程的中间产物，可在「账号池 → 待确认」逐个删除或核验。
- 额度口径：新号 Pro 试用 23333 字/周（3 天），到期后 2000 字/周；阈值 200 在两种口径下都安全（10% / 1%）。

## E. 结论

这次事故不是单点，而是「额度读不到 → 盲换号 → 注册 → 清会话」的级联。
2.9.0 把级联的每一环都装上了闸：读不到就停手、注册放到后台、失败恢复会话、
跨进程串行化、进程树清理。剩下的 C1/C2 是**能力扩展**，不是故障源。
